## Schema Design Decisions

### 1. UUID Pattern for `floorplan_id`

**Decision**: Use regex pattern validation for UUID format.

```json
"pattern": "^[a-f0-9]{8}-[a-f0-9]{4}-[a-f0-9]{4}-[a-f0-9]{4}-[a-f0-9]{12}$"
```

**Rationale**: Ensures consistency with the existing output folder naming convention (`88c9e30d-b1b1-4b5e-8fe1-f54b04a74396_floorplan_output/`).

---

### 2. Proto Value Pattern

**Decision**: Enforce `^[0-9]+L$` pattern (e.g., "16L").

**Rationale**: Matches the format used in `merch_mix_max.json` and the `_calculate_standing_tables()` function which parses `proto_str.replace('L', '')`.

---

### 3. Clinic Fixture Enum

**Decision**: Strict enum validation for fixture names.

```json
"enum": ["ROC_clinic", "Clinic_with_sink", "Clinic_regular"]
```

**Rationale**: These are the only valid clinic types defined in `fixture_dict` in `DXF_Controller.py`.

**Alternative Considered**: Open string type. Rejected because invalid fixture names would cause runtime errors.

---

### 4. Orientation Combo Enum

**Decision**: Strict enum for orientation values.

```json
"enum": ["H", "V"]
```

**Rationale**: 
- `H` = Horizontal (door facing retail area)
- `V` = Vertical (door facing sideways)

These are hardcoded in `plan_clinic_best_ranker()` using `itertools.product(["H", "V"], repeat=n)`.

---

### 5. Mirror Scale Values

**Decision**: Restrict to `[-1.0, 1.0]` enum.

```json
"items": { "type": "number", "enum": [-1.0, 1.0] }
```

**Rationale**: The mirroring logic in `DXF_Controller.py` only uses three combinations:
- `[1.0, 1.0]` - No mirroring
- `[1.0, -1.0]` - Vertical flip
- `[-1.0, 1.0]` - Horizontal flip

---

### 6. Zone ID Pattern

**Decision**: Regex pattern `^Zone_[0-9]+$`.

**Rationale**: Zone IDs are generated programmatically in `distribute_top_wall_segment()` as "Zone_1", "Zone_2", etc.

---

### 7. Euro Pattern Names Enum

**Decision**: Strict enum for pattern names.

```json
"enum": [
  "row_wise_even_rows",
  "row_wise_odd_rows", 
  "column_wise_even_cols",
  "column_wise_odd_cols",
  "None"
]
```

**Rationale**: These are the only patterns generated by `analyze_placement_patterns()`. "None" is used when no valid patterns exist.

---

### 8. Coordinate Array Structure

**Decision**: Use array format `[x, y]` instead of object format `{"x": ..., "y": ...}`.

**Rationale**: Matches the existing code in `DXF_Controller.py`:
```python
"target_center": [round(target_center.x, 2), round(target_center.y, 2)]
```

---

### 9. Rank Minimum Value

**Decision**: `minimum: 1` (ranks start at 1, not 0).

**Rationale**: Ranks are assigned using 1-indexed loop:
```python
for i, layout in enumerate(all_valid_layouts):
    layout["Rank"] = i + 1  # 1-indexed
```

---

### 10. Empty Arrays Allowed

**Decision**: Allow empty `ranked_layouts` and `remaining_fixtures_queue` arrays.

**Rationale**: These are valid states:
- Empty `ranked_layouts`: No valid clinic placements possible
- Empty `remaining_fixtures_queue`: All clinics successfully placed

---

### 11. Additional Properties

**Decision**: Allow additional properties (not using `additionalProperties: false`).

**Rationale**: 
- Debug fields like `_debug_zone`, `_debug_depth_score` are included in production data
- Future-proofs the schema for new fields
- Annotation fields (starting with `_`) in example files won't cause validation errors

---

### 12. Back Room Location Nullable

**Decision**: Allow `null` as valid value for `back_room_location`.

```json
"type": ["string", "null"],
"enum": ["left", "right", "middle", null]
```

**Rationale**: `detect_back_corner_room()` returns `None` when no back room is detected.

## Usage

### Validating a Plan File

```python
import json
from jsonschema import validate, Draft7Validator

# Load schema and data
with open("schemas/plans_schema.json") as f:
    schema = json.load(f)
    
with open("your_plan.json") as f:
    data = json.load(f)

# Validate
validate(instance=data, schema=schema)
```
